# 规格：多书分段拆解实验室

> 版本：v0.1  
> 日期：2026-08-09  
> 状态：已按产品负责人连续推进授权进入实现

## 1. 目标与默认假设

为历史重生、都市重生网文作者提供本地参考作品库。作者可以导入多本自有、已授权或公版作品，把超长作品切成可独立分析的区段，再跨书选择区段，萃取并融合时代、核心欲望、冲突因果、资源体系、关键场景顺序和结局。

默认假设：

1. 参考原文只保存在本机，与现实资料、作者正文和正式事实分层存储。
2. 单书默认每 500,000 个 Unicode 字符形成一个“分析区段”；优先在章节边界切分，无法识别章节时再按字符边界切分。
3. 500,000 字区段不会一次性发送给模型。系统先按不超过约 50,000 字的内部处理块执行 Map，再把结构化结果 Reduce 成区段模式卡。
4. 项目参考库允许多本作品；一次多书合成至少选择两本不同作品的区段。合成阶段只读取结构化模式卡，不读取参考原文。
5. 每条结论必须保留作品、区段、字符范围以及可选章节范围来源。
6. 第一条切片支持 UTF-8 TXT/Markdown，单文件不超过 20 MB；PDF 在解析安全测试完成后接入。

## 2. 用户工作流

1. 选择项目，打开“拆书实验室”。
2. 选择 TXT/Markdown，声明权利基础，设定区段目标字数或使用默认 50 万字。
3. 本地读取文件，API 二次校验扩展名、字节数、字符数和空字节，然后写入隔离参考库。
4. 系统显示作品总字数、区段数量，以及每段的字符范围和章节范围。
5. 作者从多本书中勾选若干区段，分别运行区段拆解。
6. 系统将处理块结果汇总为六维模式卡，并保留来源回链。
7. 作者跨书选择模式卡，运行多书合成，得到共同模式、差异、可组合方案和风险提示。
8. 只有作者确认且通过原创性门禁的新作方案才能进入叙事规划器；原文和具体情节证据不能进入正文模型上下文。

## 5. 代码风格

公开接口使用稳定领域词汇，原文不出现在工作区总响应中：

```python
class ReferenceSegment(BaseModel):
    id: str
    reference_work_id: str
    ordinal: int
    start_char: int
    end_char: int
    character_count: int
    chapter_start: str | None
    chapter_end: str | None
```

所有 SQL 使用参数化参数；所有模型输入有长度、枚举和空字节校验；错误响应不携带本地路径、原文或模型内部异常。

## 6. 测试策略

- 领域测试：章节边界附近切分、无章节标题回退、300 万字生成 6 个约 50 万字区段、字符范围无重叠无遗漏。
- API 测试：多书导入、非法扩展名、空文件、超限内容、空字节、项目不存在。
- 隔离测试：工作区和作品列表不返回原文；AI 写章上下文不包含参考区段表。
- 后续模型契约：500,000 字区段按内部块 Map；每张模式卡覆盖六维并保留来源；多书合成至少包含两个不同作品。
- 前端测试：导入两本书后可以查看并勾选跨书区段，默认区段大小显示为 50 万字。
- 全量门：`pnpm run verify`、桌面 release 构建、依赖高危审计和真实浏览器验收。

## 7. 边界

### 始终执行

- 只接受作者自有、明确授权或公版作品，并保存权利声明。
- 导入前后都校验格式、大小、字符数和空字节。
- 原文、证据、模式卡、新作方案和正式事实使用不同类型与查询接口。
- 外部调用前显示将发送的处理块范围；调用结果保留模型和来源谱系。

### 需要产品负责人确认

- 默认把参考原文上传到云端或建立共享参考库。
- 放宽 20 MB 单文件上限、接入付费解析服务或改变权利声明。
- 允许高风险原创性结果绕过门禁进入正文生成。

### 绝不执行

- 抓取付费网站、破解 DRM 或导入来源不明的商业语料库。
- 让正文 Agent 直接检索参考原文或长证据段落。
- 提供“一键仿写某书/某在世作者”或复刻专名、人物组合、原句和独特场景序列。
- 在日志、错误或工作区总响应中暴露参考原文。

## 8. 成功标准

1. 导入一部 300 万字合成作品时，默认生成 6 个连续、无重叠、无遗漏的约 50 万字区段。
2. 至少两本作品的区段可以同时选择；作品、区段元数据和结果来源谱系可在重启后恢复。界面勾选属于一次分析会话，不作为长期状态。
3. 列表和工作区接口只返回元数据，不返回区段原文。
4. 区段模式卡分别输出时代、核心欲望、冲突因果、资源体系、关键场景顺序和结局，并能回到来源范围。
5. 多书合成只使用模式卡，输出共同规律、差异、可组合建议和原创性风险。
6. 参考原文无法进入现有 AI 章纲或正文上下文。
