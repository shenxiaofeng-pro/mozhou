# 墨舟稳定数据目录与数据库迁移规格

## 背景

当前数据库默认保存在进程启动目录下的 `.mozhou-data/mozhou.db`。桌面应用、命令行和开发服务器的启动目录可能不同，因此同一台机器上会出现“作品消失”的假象；安装目录也可能没有写权限。数据库结构升级目前没有显式版本、升级前备份或完整性门禁。

## 目标

1. 默认数据库位置与启动目录无关，使用操作系统的用户应用数据目录。
2. 首次升级时无损复制旧库，旧库原件保持不变。
3. 数据库结构升级具有版本号，且只在升级前创建一致性备份。
4. 对损坏库或比当前程序更新的数据库拒绝写入，避免以空库掩盖问题。

## 路径规则

- `MOZHOU_DATA_DIR`：显式配置时优先，目录内数据库名固定为 `mozhou.db`。
- macOS：`~/Library/Application Support/com.lingjing.mozhou/mozhou.db`
- Windows：`%LOCALAPPDATA%/Mozhou/mozhou.db`；缺失时依次回退 `%APPDATA%` 和 `~/AppData/Local/Mozhou`。
- Linux：`$XDG_DATA_HOME/mozhou/mozhou.db`；缺失时为 `~/.local/share/mozhou/mozhou.db`。

显式配置 `MOZHOU_DATA_DIR` 代表用户有意选择一个库，不自动迁移当前目录旧库。如确需指定迁移来源，可设置 `MOZHOU_LEGACY_DATA_DIR`。

## 旧库迁移

默认模式下，目标库不存在且 `<启动目录>/.mozhou-data/mozhou.db` 存在时执行一次迁移。迁移必须：

- 使用 SQLite Backup API，确保 WAL 模式下也得到一致快照；
- 先写临时文件，通过完整性检查后原子改名为目标文件；
- 保留旧库及其 WAL/SHM 文件，不移动、不删除；
- 目标库已存在时不覆盖；
- 失败时抛出明确异常并阻止应用继续启动，不创建空库。

## Schema 升级与备份

- 使用 SQLite `PRAGMA user_version` 保存结构版本，当前版本为 `3`。
- 迁移注册表位于 `services/api/app/migrations/`，必须按 v1→v2→v3 连续执行；缺号或乱序在启动前视为工程错误。
- 新库直接初始化到当前版本，不产生升级备份。
- 已存在且版本更旧的库：先运行 `PRAGMA quick_check`，通过后在同级 `backups/` 目录创建一致性备份，再升级并写入新版本。
- 所有升级先在同目录暂存副本上执行；只有迁移和 `quick_check` 全部成功才替换原库，中途失败会清理暂存副本并保留原库及备份。
- 备份名包含目标版本和 UTC 时间，永不覆盖；本批次不自动删除历史备份。
- 已存在且版本相同：检查完整性，不重复备份。
- 数据库版本高于程序支持版本：拒绝打开，避免旧程序破坏新数据。
- 完整性检查失败：拒绝迁移或升级，保留所有现有文件。

## 验收标准

1. 从不同工作目录启动时，默认路径一致。
2. 旧库的项目/章节可从新路径读取，旧库仍在原处。
3. 首次升级创建一个可读取的备份并写入 schema version；第二次启动不再增加备份。
4. 损坏库与未来版本库均不会被修改，启动给出领域错误。
5. 后端单测、静态检查和整仓发布门全部通过。
6. v1、v2 夹具可顺序升级到 v3；注入任一中间迁移失败时，原库字节、版本和内容不变。

## 非目标

- 本批次不实现项目级导出/恢复界面。
- 本批次不实现历史备份清理策略。
- 桌面 FastAPI sidecar、动态端口和安装包属于下一竖切。
