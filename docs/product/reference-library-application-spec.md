# 规格：独立拆书库与作品应用

> 版本：v0.1  
> 日期：2026-08-09  
> 状态：首个端到端切片已交付

## 1. 目标与假设

把现有嵌在章节导演台里的拆书实验室升级为当前作品的独立管理页面。作者在这里管理参考作品、运行多书萃取、长期保存六维模式卡，再选择其中若干抽象维度应用到当前作品。

本切片采用以下假设：

1. “应用到某本书”首先指应用到当前打开的创作项目；作者打开另一项目后，可在该项目的拆书库执行同样流程。跨项目共享参考原文另行设计，避免未经确认复制隔离语料。
2. AI 萃取成功后立即保存为候选模式卡，刷新或重启后仍可查看。
3. 应用不是写正文，也不直接修改章纲、事实或人物关系；它只创建一个当前作品的“参考结构蓝图”。
4. 章节 AI 只能读取作者已应用蓝图中的维度摘要、可迁移逻辑、人物关系重组和作者备注；不能读取参考原文、处理块、来源证据或未应用模式卡。
5. 作者必须选择至少一个维度，并确认会重写人物、地点、专名和具体场景后才能应用。

## 2. 用户工作流

1. 在作品顶部点击“拆书库”，进入独立页面；点击“返回创作台”回到章节工作区。
2. 导入多本合法参考作品，按默认 50 万字查看和选择区段。
3. 勾选外部处理确认，运行跨书六维萃取。
4. 系统把结果持久化为候选模式卡，展示来源回链、共同规律、差异和原创性风险。
5. 作者在模式卡上选择时代、核心欲望、冲突因果、资源体系、关键场景顺序、结局中的一个或多个维度，填写如何用于当前作品的备注。
6. 作者确认原创改编边界后点击“应用到《当前作品》”。
7. 工作区显示已应用蓝图；后续 AI 章纲/正文上下文只收到所选抽象维度。

## 3. 技术与项目结构

- React 页面：`ReferenceLibraryPage.tsx`。
- 拆书功能：`ReferenceLabPanel.tsx` 与模式卡应用组件。
- 契约：`ReferencePatternCard`、`ReferencePatternApplication`、`ApplyReferencePatternRequest`。
- 数据表：`reference_pattern_cards`、`reference_pattern_applications`。
- API：保存萃取结果；应用模式卡到当前项目。

```bash
pnpm run verify
pnpm audit --audit-level high
pnpm run desktop:build
```

## 4. 测试策略

- 数据库：旧库增量建表；模式卡和应用蓝图重启可恢复。
- API：萃取结果持久化；跨项目卡片不能应用；重复维度、空维度和未确认原创改编被拒绝。
- 隔离：工作区与应用响应不含参考原文；章节上下文只含已应用抽象维度。
- 前端：独立页面导航、刷新可见模式卡、选择维度、确认后应用到当前作品。
- 真实浏览器：验证页面层级、返回路径、按钮门禁和无控制台错误。

## 5. 边界

### 始终执行

- 使用参数化 SQL 和 Pydantic 输入校验。
- 模式卡、应用蓝图和参考原文分表、分模型、分查询。
- 每张模式卡记录模型、来源区段和创建时间；应用蓝图记录作者选择的维度。
- 章节上下文只编译已应用蓝图的抽象字段。

### 需要确认

- 建立跨项目共享参考原文库或把参考作品从一个项目复制到另一个项目。
- 让模式卡自动改写现有书纲、卷纲、章纲或正文。
- 允许未通过后续相似度门禁的方案自动批量生成章节。

### 绝不执行

- 把参考原文、原句、专名或具体场景证据加入章节生成上下文。
- 未经作者确认自动应用模式卡。
- 用“应用”绕过正式事实和正文 revision 门禁。

## 6. 成功标准

1. 拆书库有独立全页入口，不再占用本章导演台空间。
2. AI 六维萃取成功后模式卡持久化，刷新项目后仍存在。
3. 作者可选择部分维度并应用到当前作品，应用状态可恢复。
4. 未确认、空维度、跨项目或重复应用均被安全拒绝。
5. 章节 AI 上下文包含已应用摘要，不包含 `reference_text`、区段内容或未应用卡。
