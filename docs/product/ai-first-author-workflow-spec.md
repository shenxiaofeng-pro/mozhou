# AI 主写、作者主导的网文创作闭环规格

> 状态：已确认，进入实施
> 日期：2026-09-11
> 适用题材：历史重生、都市重生、东方玄幻、西方奇幻

## 1. Objective

把墨舟从“功能齐全但入口分散的写作工具”收敛为一条连续的作者生产线：作者负责选题、审美判断和最终决定，AI 负责整书推演、完整单章初稿、局部改写、事实提取和模式原创迁移。

目标工作流：

```text
人工确认选题
  → 选择合法来源的多书写作模式配方
  → AI 生成 3 套原创迁移方案
  → 人工确认整书蓝图
  → AI 生成完整单章候选并自检
  → 人工比较、局部调整和批准
  → 从最终正文提取事实与作者偏好候选
  → 人工确认后进入下一章上下文与滚动计划
```

成功不是“按钮更多”，而是作者可以在一个连续界面内完成上述闭环，且任何旧 AI 结果都不能覆盖较新的人工修改。

## 2. 已确认假设

1. 首发仍为 macOS、本地优先、单用户工作台。
2. 首轮模型支持 OpenAI-compatible；Ollama 原生安装与适配仍属于后续范围。
3. AI 默认可一键运行至“完整单章候选稿”，不会自动写入正文、批准章节、正式事实或自动发布。
4. 参考资料只接受作者自有、明确授权或公版内容；不实现付费站抓取、DRM 绕过或来源不明语料收集。
5. 参考小说原文只进入拆解服务；正文模型只接收作者批准的抽象模式档案，不接收参考原文。
6. 时代、核心欲望、冲突因果、资源体系、关键场景顺序和结局结构允许按维度保留、调整或重构；人物、人物关系、专名、独特场景和表达默认重构。
7. 不增加云协作、支付、移动端、平台自动发布或无人值守多章生成。

## 3. 核心领域对象

### 3.1 TopicDecision

作者冻结的选题版本，至少包含：目标平台/读者、题材细分、一句话命题、核心欲望、长期承诺、前三章承诺、商业与敏感边界、禁止项和参考作品用途。AI 方案只是候选，只有作者确认后才成为当前选题。

### 3.2 CraftPatternCard

从单个参考区段或单本作品提取的可审计技法卡。除既有六维故事骨架外，覆盖：

- 开篇与章末钩子机制
- 承诺、升级、兑现和反转节奏
- 爽点、挫折和情绪回报间隔
- 信息揭示率和伏笔回收周期
- 场景进入/退出、场景/过场比例
- POV、叙事距离、对话/动作/解释比例
- 章节、段落和句长分布
- 玄幻/奇幻升级阶梯、能力代价、阵营推进模式

每条模式必须保存来源作品、区段、章节或字符范围、证据摘要、置信度和抽象层级；不得保存可供正文模型复现的长段原文。

### 3.3 WritingPatternRecipe

作者从 1–5 本作品、多个约 50 万字阶段卡中组合的项目写作配方。每个来源可指定学习项、反例项、权重、适用卷/章节范围，以及 `preserve / transform / avoid` 策略。冲突必须显式呈现，不能静默平均。

### 3.4 WritingPatternProfile

由当前选题、参考配方和作者锁定项编译出的紧凑、版本化档案。它是整书规划、卷纲、滚动章纲、正文、局部改写和审校共同使用的唯一参考模式输入，只包含抽象规则与来源指纹。

### 3.5 ChapterProduction / WritingOutcome

一次完整章节生产关联冻结 ContextPacket、Prompt、Provider、Job、候选版本、质量报告、作者决定和最终章节版本。旧候选、已批准章节和锁定片段均不可被绕过覆盖。

### 3.6 CanonDeltaCandidate / AuthorPreferenceCandidate

章节批准后，从最终不可变正文提取带证据的事实变化候选，并从 AI 候选与最终稿差异中提取写作偏好候选。二者未经作者确认均不得进入下一章上下文。

## 4. 功能要求

### 4.1 人工选题

- 新项目默认进入选题台，不以空白正文作为第一任务。
- 作者可以手写选题，也可以要求 AI 给出 3 套候选并按关键维度并排比较。
- 作者可锁定字段、标记“不喜欢原因”并只重生成部分字段。
- 选题确认生成不可变 revision；后续修改会标记整书蓝图及下游计划待复核。

### 4.2 长篇与多书模式

- 单本作品可以独立分析；多书融合不再是拆解的前置条件。
- 默认按约 50 万中文字符生成阶段卡；300 万字作品可形成约 6 张可单独浏览、比较和复用的阶段资产。
- 内部可继续使用约 5 万字 Map 任务，但作者面对的是“阶段卡 → 单书演变卡 → 多书配方”三级资产。
- 拆解前展示字符/token、预计 Map/Reduce/Fusion 调用数、模型、缓存命中与费用估算。
- 每条模式可以回到具体章节或字符范围，由作者修正或否定。

### 4.3 原创迁移与门禁

- AI 根据选题和配方生成 3 套实质不同的原创迁移方案。
- 作者锁定字段不可被重生成；人物关系默认重构。
- 原创性检查绑定“聚合配方 revision + 最终 BookBlueprint revision”，不能只检查单张参考应用。
- 高风险结果只能调整或重生成；失败或弃用的配方可停用/归档，不得永久阻断整个项目。

### 4.4 AI 单章主写

- 单一主流程完成上下文冻结、章纲、写前检查、完整正文候选和候选质量报告。
- 写前检查必须能阻断明显缺失读者承诺、状态变化、情绪兑现或章末悬念的生成，而不是永远通过。
- 候选正文可以在未采用时接受七维审校。
- 所有采用操作必须验证候选基准 revision；旧候选只能比较或重新生成。

### 4.5 人工调整

- 支持正文/候选左右对照、候选内编辑、段落/场景级采用、局部重生成、锁定、撤销和多个候选合并。
- 局部命令至少包括扩写、压缩、改写、增强冲突、增强情绪和自定义意图。
- 每次 AI 改写仍生成新候选或变更集，不直接覆盖正文。

### 4.6 连载反馈

- 批准章节后自动从最终正文生成 typed Canon delta 候选，覆盖人物、关系、资源、地点、知识、伏笔、境界/能力与时间线。
- 每条候选包含精确正文证据；作者可批量接受、编辑或拒绝。
- 作者确认的修改偏好进入后续上下文；未确认、已拒绝或已删除偏好不得进入。
- 完成回灌后自动补齐未来 3–5 章滚动计划，并显示“开始下一章”主操作。

## 5. 非功能要求

- 数据可靠性：旧 AI 结果覆盖作者新稿为 0；重复任务副作用为 0。
- 可追踪性：所有 AI 候选可回到 ContextPacket、Prompt、Provider、模型和来源模式 revision。
- 隐私：参考原文、API Key 和长篇 diff 不进入日志、诊断包或正文生成上下文。
- 性能：30 万字项目工作区常规操作不退化；300 万字参考作品使用可恢复分块任务。
- 可访问性：1280、1040 和 760 像素宽度核心流程可达；键盘焦点可见；模态正确锁定和恢复焦点；正文保持清晰焦点环。
- 成本：所有新增长模型任务调用前都有范围与费用预览。

## 8. Code Style

后端保持严格 Pydantic 输入、参数化 SQL、短事务和显式 revision：

```python
if chapter.revision != run.expected_chapter_revision:
    raise ConflictError("候选基于旧版本，请重新生成或查看差异")
```

前端使用面向作者的动作名称，避免暴露内部 Job/Artifact 术语：

```tsx
<button type="button" onClick={openCandidateComparison}>
  比较并调整候选稿
</button>
```

新增领域行为放入有明确边界的服务，不继续扩大单个路由、模型或仓储文件；禁止为拆文件而创建无业务 Depth 的薄包装。

## 9. Testing Strategy

1. 缺陷先写回归：尤其覆盖“旧 run + 当前 revision 参数”仍必须冲突。
2. 每个里程碑采用最小纵切，专项测试通过后再运行全量验证。
3. 数据迁移测试覆盖 v22 真实升级、失败回滚、重复启动和归档往返。
4. Provider 使用确定性 fake/recorded adapter；自动化不得产生未确认费用。
5. 增加一条黄金旅程：选题确认 → 2–5 本参考配方 → 原创迁移 → AI 完整单章 → 局部调整 → 定稿 → 回灌 → 下一章。
6. 增加一条恢复旅程：高风险配方停用后 AI 恢复；旧候选和旧原创性报告均无法越过版本门。
7. 四题材分别建立结构与质量黄金样本；真实作者测试单独记录，不能用自动化冒充。

## 10. Boundaries

### Always

- 所有 AI 输出先进入候选域。
- 所有正文、事实、选题、配方和蓝图更新使用 revision/版本指纹。
- 所有 SQL 参数化，上传校验扩展名、MIME、大小和压缩包安全边界。
- 每个迁移先备份、可重复运行并有归档兼容测试。
- 每个纵切更新 `PROGRESS.md` 并运行其定义的验证。

### 已授权但必须保守执行

- 为本规格增加数据库 schema 与归档版本。
- 重组作者工作台信息架构和新增本地 API。
- 增加模式提取、原创迁移、事实与偏好候选任务。

### Never

- 不自动批准正文、事实、偏好或参考蓝图。
- 不抓取付费小说站、不绕过 DRM、不隐藏模型费用。
- 不把参考原文或特定作者声音交给正文模型模仿。
- 不删除历史版本、失败任务证据或降低现有测试门槛。

## 11. Success Criteria

1. 新作者可在 15 分钟内从选题确认得到可编辑的完整首章候选，无需填写底层 schema。
2. 300 万字单书可恢复地生成约 6 张阶段卡，并能与其他作品按不同用途组成配方。
3. 每条写作模式可追到章节/字符证据；正文上下文不含参考原文。
4. 任何旧候选即使携带当前正文 revision，也不能覆盖作者新稿。
5. 配方、整书蓝图和正文候选的原创性报告与各自 revision 绑定。
6. 作者能局部调整 AI 候选并清晰比较差异，所有修改可撤销。
7. 最终正文中新人物、关系、资源和世界规则能形成带证据候选，经确认后进入下一章。
8. 四题材黄金旅程、完整 `pnpm run verify` 和真实浏览器验收通过。
9. 5–10 位作者各完成至少 10 章试写后，才能宣称产品闭环通过真实作者验证。

## 12. Open Questions / External Dependencies

当前没有阻断工程实施的产品问题。真实作者闭环验证需要外部参与者和真实模型费用，工程阶段只完成测试协议、数据采集和零费用演练；到该里程碑时如仍没有参与者或费用授权，将如实标记为外部待验收，不降低标准。
