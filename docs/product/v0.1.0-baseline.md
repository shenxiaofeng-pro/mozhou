# 墨舟 0.1.0 基线契约

> 冻结标签：`v0.1.0-baseline`
> 基线提交：`86cd5bc210807542702df39c04a2951f52423b95`
> 冻结日期：2026-08-09

本文件记录 PLAN M0 实施前可恢复基线。标签保存当时的源码、依赖锁和协议实现；后续里程碑可以做兼容扩展，但不能无迁移地破坏用户数据或既有归档。

## 数据协议

- SQLite `PRAGMA user_version`：2。
- 默认数据库位于操作系统用户应用数据目录；`MOZHOU_DATA_DIR` 可显式覆盖。
- schema 升级前必须通过完整性检查并创建版本化备份。
- 未来版本或损坏数据库必须拒绝写入，不能静默重建或覆盖。
- 当前 schema 定义以标签中的 `services/api/app/database.py` 为准。

任何数据结构变更必须增加显式顺序迁移、升级/重复启动/失败回滚测试，并保留旧版本数据库夹具。

## 本地 API 协议

- FastAPI 应用版本：0.1.0。
- 基线路由：35 个，定义在 `services/api/app/main.py`。
- Web 与桌面只能通过共享契约和 API 客户端访问，不直接读取 SQLite。
- 破坏性请求/响应变更必须提供兼容期或版本化端点，并同步更新 TypeScript 契约、API 测试和本文件。

## 项目归档协议

- `format`：`mozhou-project`。
- `format_version`：1。
- `schema_version`：2。
- 最大未压缩归档：256 MiB。
- 归档使用固定表/列白名单和 SHA-256 完整性校验；导入始终创建项目副本并重映射标识，不覆盖现有项目。
- 恢复点保存压缩归档，恢复点元数据不递归写入项目归档。

新增全局参考资产等不属于单项目的数据时，必须显式定义其导出边界；改变既有格式需提升 `format_version` 并保留旧版本导入测试。
