# 码字日历体验优化规格

## 目标

为中文网文作者提供一个打开后立即看见“今天写了多少、是否延续创作、近 42 天节奏如何”的码字日历。首屏优先服务当天写作决策，历史记录退居为紧凑趋势；统计术语使用作者能直接理解的中文。

## 技术栈与结构

- React + TypeScript：`apps/web/src/components/AuthorToolsDialog.tsx`
- CSS：`apps/web/src/styles.css`
- FastAPI 领域服务：`services/api/app/author_productivity.py`
- Vitest / Testing Library：`apps/web/src/components/AuthorToolsDialog.test.tsx`
- pytest：`services/api/tests/test_author_productivity.py`

不新增依赖、不迁移数据库、不改变 42 天 API 契约。

## 设计系统

- 主题：作者的“当日稿页 + 历史稿袋”，避免通用后台仪表盘。
- 色彩：墨色 `#173031`、松石 `#2f756d`、朱砂 `#c85f32`、纸白 `#fffdf8`、雾灰 `#e9ece6`、删改棕红 `#98472f`。
- 字体：标题克制使用宋体，正文与数据沿用系统黑体；辅助文字不小于 12px，普通文本对比度至少 4.5:1。
- 标志性结构：近 7 天展开成可读稿页，过去 35 天压缩成五条稿袋索引。

```text
┌ 近42天 · 日期范围 ─────────────── 今日字数变化 ┐
│ 码字节奏 / 今日提示 / 回到正文 / 调整目标       │
├ 近42天变化 ─ 连续创作 ─ 达标天数 ─ 创作日 ─────┤
│ 近7天：7张展开日卡，今天始终在首屏               │
├ 过去35天：5条紧凑日期索引，最近一条在最上方 ───┤
└───────────────────────────────────────────────┘
```

## 行为口径

1. “今日净增”改为“今日字数变化”，“六周净增”改为“近42天变化”。
2. 负数显示为“正文减少”，状态显示“以修改为主”，并解释正负数含义。
3. 今天尚无活动时，连续创作从昨天向前计算；今天有正向或负向正文变化时都计为创作日。
4. 近 7 天始终展开并包含今天；过去 35 天按最近到最早排列为紧凑趋势。
5. 全部为空时仍显示近 7 天，但提供“回到正文写作”行动，不渲染 42 张同尺寸空白大卡。
6. “调整日目标”复用既有连载工作台，不建立第二套设置。
7. 作者工具弹窗打开后聚焦关闭按钮，支持 Escape，Tab 焦点不离开弹窗，关闭后恢复触发点。
8. 分类导航使用 tablist/tab/tabpanel 语义，异步切换有可感知的加载状态。

## 命令

- Web 专项：`pnpm --filter @mozhou/web exec vitest run src/components/AuthorToolsDialog.test.tsx`
- API 专项：`uv run --project services/api --no-sync pytest services/api/tests/test_author_productivity.py`
- 完整验证：`pnpm run verify`
- 开发运行：`pnpm run dev`

## 测试策略

- API：覆盖今天未写不中断昨日连续记录、负向正文变化计入连续创作。
- 组件：覆盖近 7 天优先、过去 35 天、易懂文案、今天标记、按钮回调、标签语义、加载状态和 Escape。
- 浏览器：1280×720、1040×720、760×720 检查今天可见、无页面横向溢出、局部滚动可控、焦点进入弹窗、控制台零 warning/error。

## 边界

- 始终：候选章节版本不进入统计；保留有符号净字数；使用既有日目标。
- 需要另行决策：新增月历导航、按项目设置独立时区、保存无字数变化的编辑活动。
- 禁止：以候选稿污染统计；静默改变章节目标；为视觉效果新增网络字体或第三方图表库。

## 验收标准

- 常见 720px 高度打开后可见完整近 7 天和今天卡片。
- 辅助文字至少 12px，关键普通文本对比度达到 4.5:1。
- 760px 下图例不被裁切，页面本身不出现横向滚动。
- 连续创作语义、键盘关闭与焦点恢复有自动化回归。
- 完整 lint、类型、测试、构建、sidecar 与 Rust 检查通过。
