# 项目归档与恢复规格（R2.3）

## 1. 问题与目标

作者需要把一部作品完整带走、在另一台设备恢复，或在重大改写前留下可回退的快照。首版必须优先保证原稿不被覆盖，并覆盖正文、设定账本、时间线、生成记录和拆书资产。

成功标准：

- 单个项目可以导出为一个 UTF-8 JSON 归档，包含该项目关联的全部业务表数据和参考作品原文。
- 导入归档后生成新的项目副本，原项目及已有项目不发生修改。
- 恢复点可创建、列表和恢复；恢复同样生成新副本。
- 篡改、超限、未知版本或越权结构的归档在事务写入前被拒绝。

## 2. 用户流程

1. 作者在作品书架点击“导出归档”，浏览器/桌面端保存 `.mozhou.json` 文件。
2. 作者点击“导入作品副本”，选择归档文件；校验通过后，书架出现“原书名（恢复副本）”。
3. 作者可为某部作品创建带备注的恢复点，在恢复点列表查看创建时间和体积。
4. 点击“恢复为副本”后，新副本进入书架；任何流程都不提供覆盖原项目的选项。

## 3. 归档协议

固定字段：

- `format`: `mozhou-project`
- `format_version`: `1`
- `exported_at`: UTC ISO-8601 时间
- `source_project_id` / `source_project_title`
- `schema_version`: 导出程序数据库版本，仅作诊断信息
- `tables`: 固定白名单表到行数组的映射
- `checksum_sha256`: 对除本字段之外所有字段的规范 JSON 计算 SHA-256

规范 JSON 使用 UTF-8、对象键排序、紧凑分隔符；归档不包含恢复点，防止递归快照。格式版本独立于数据库版本，数据库继续升级时仍可维持协议兼容。

## 4. 数据范围与一致性

白名单包含：项目、章节、AI 生成运行与事件、时间线、事实变更、未来知识、人物与资源、伏笔、素材卡、参考作品与区段原文、结构模式卡及应用记录。

导出在一个 SQLite 读事务内完成。导入先完成结构、列集合、UUID、数量、引用和校验和验证，再在一个写事务内插入；任一步失败则整次导入回滚。

所有行主键生成新 UUID，所有外键和受支持 JSON 字段内的 UUID 同步重映射。项目标题追加“（恢复副本）”，最长 120 字符。原始时间保留，副本项目的 `updated_at` 使用恢复时间，便于在书架置顶。

## 5. 安全与资源边界

- API 只接受 `application/json`；`Content-Length` 和流式累计体积均限制为 256 MiB。
- 只允许固定表名和精确列集合；SQL 仅使用内置语句与参数，不接受归档提供的表名或 SQL。
- 每张表限制最多 100,000 行；项目表必须恰好一行，且所有数据必须归属于同一个项目。
- 所有主键必须是互不重复的 UUID；外键必须指向归档内已知 UUID。
- 校验和通过后仍要以当前业务模型验证题材、状态机、时间、参考区段范围、模式卡维度与来源引用；SHA-256 用于完整性检查，不被当作可信签名。
- JSON 嵌入列必须是合法 JSON；压缩恢复点解压同样执行 256 MiB 上限，防止压缩炸弹。
- 错误响应不回显归档正文、路径、SQL 或底层数据库错误。

## 6. 恢复点

恢复点保存同一归档协议的 zlib 压缩字节、原始大小、SHA-256、标签、类型和创建时间。列表只返回元数据，不加载正文。恢复时先限量解压并重新执行完整导入校验，然后创建新项目副本。

首版不自动删除恢复点，也不导出恢复点。后续可在有明确保留策略和二次确认后增加删除与自动轮换。

## 7. 接口

- `GET /api/projects/{project_id}/export`
- `POST /api/project-imports`
- `POST /api/projects/{project_id}/recovery-points`
- `GET /api/projects/{project_id}/recovery-points`
- `POST /api/recovery-points/{recovery_point_id}/restore`

导出返回归档 JSON；导入和恢复返回完整 `Workspace`；创建/列表返回恢复点元数据。

## 8. 验证

- 后端：完整导出、校验和、篡改拒绝、未知字段/版本/超限拒绝、全量 ID 重映射、原项目不变、恢复点压缩与恢复、事务失败不留半成品。
- 前端：导出下载、文件体积/格式提示、导入后书架刷新、恢复点创建与恢复、操作中禁用和错误反馈。
- 发布门：ruff、mypy、pytest、Vitest、TypeScript、Web build、PyInstaller sidecar、Cargo check 全通过。
