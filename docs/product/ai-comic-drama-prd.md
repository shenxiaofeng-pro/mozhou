# AI 漫剧改编工作台 PRD

## 1. 产品结论

墨舟新增“AI 漫剧改编工作台”，服务已经拥有或正在连载小说的中文网文作者。作者选择一卷、若干章或连续剧情段，系统把小说内容转换为一季 AI 漫剧的季纲、分集大纲、逐集完整剧本和结构化制作包；季纲、每集大纲和每集剧本均停在候选区，只有作者明确确认后才成为漫剧项目的正式版本。

首版止于“完整文字剧本 + 可交给图片/视频模型的制作包”，不生成图片、音频或最终视频。

## 2. 用户与核心任务

目标用户是需要把自有小说改编为 AI 漫剧、但不希望手工重做整套影视结构的作者。核心任务是：

> 在不破坏小说原稿和正式事实的前提下，把选定剧情段重构成节奏可控、来源可追溯、可逐集批准的 AI 漫剧文字生产包。

用户成功标准：

1. 能从连续小说章节创建一个独立漫剧项目。
2. 能得到覆盖目标集数的季纲和分集大纲，并逐集确认。
3. 能为已确认大纲生成带场次、动作、对白、旁白和画面重点的完整剧本。
4. 能看见节奏、连续性、画面可表现性和制作复杂度问题。
5. 能导出只包含已批准剧集的 Markdown、JSON 和 DOCX 制作包。
6. 小说修改后能识别改编来源已变化，不静默覆盖已确认剧本。

## 3. 已确认的产品决策

- 目标形态：AI 漫剧，而非真人短剧。
- 改编范围：按卷、连续章节或剧情段创建项目，不一键处理整本超长小说。
- 交付深度：分集大纲，以及带场次、动作和对白的完整剧本。
- 批准方式：作者逐集确认；分集大纲与完整剧本使用两道独立批准门。
- MVP 输出：文字制作包；图片、分镜图、配音、口型、视频和平台发布后置。
- 默认运行：本地优先、单用户、复用现有 OpenAI-compatible 模型线路。

## 4. 核心体验

### 4.1 创建漫剧项目

作者从当前小说的稳定卷章目录选择连续章节，设置：

- 项目名与季名
- 目标集数（1–100）
- 单集目标时长（30–300 秒）
- 画幅（默认 9:16）
- 画风说明
- 改编强度：忠实、平衡、强节奏
- 旁白倾向和作者补充要求

系统冻结来源章节 ID、revision、内容哈希和结构摘要。已删除章节、跨项目章节、重复 ID 或非连续选择必须拒绝。

### 4.2 季纲与分集大纲

模型基于冻结来源、小说正式人物/事实/时间线和作者要求生成一个候选季方案：

- 一句话故事、本季主题、核心欲望、主冲突
- 改编策略与删改说明
- 角色合并/保留建议
- 每集标题、来源章节、开场钩子、目标、冲突、反转、情绪兑现、结尾卡点
- 每集出场人物、地点、关键道具和下一集承诺

作者先确认季方案，再逐集确认大纲。季方案采用后只创建候选剧集，不自动批准任何单集大纲。

### 4.3 单集完整剧本

只有大纲已批准的剧集才能生成完整剧本。每个场次包含：

- 场号、内/外景、地点、时间
- 出场人物
- 可见动作
- 结构化对白与说话情绪
- 旁白或内心独白
- 画面重点、场尾钩子
- 小说来源章节
- 角色、地点、服装、道具、特效和其他资产需求

候选剧本允许拒绝、重新生成或确认。确认时把场次物化到正式漫剧场次表；确认动作不修改小说正文、Canon、时间线或伏笔。

### 4.4 制作包

制作包只读取已批准剧集，包含：

- 项目与季设定
- 分集大纲
- 按场次排列的完整剧本
- 角色、地点、服装、道具和特效资产清单
- 每项资产首次出现集数与出现范围
- 小说来源映射、生成来源、版本和 SHA-256
- AI 生成内容标识提示与发布前合规清单

输出格式为 Markdown、结构化 JSON 和纯文字 DOCX。JSON 是后续图片/视频模型适配器的稳定输入协议。

## 5. 信息架构

~~~text
小说项目
  └─ 漫剧改编项目（一个季）
       ├─ 冻结来源范围
       ├─ 季纲候选版本
       ├─ 剧集 01
       │    ├─ 分集大纲候选/批准版本
       │    ├─ 完整剧本候选/批准版本
       │    └─ 正式场次与来源映射
       ├─ 剧集 02…
       ├─ 审校问题
       └─ 制作资产清单与导出
~~~

漫剧是小说的派生作品，不是小说目录的一部分。小说事实是改编输入，但漫剧新增、合并或重排的事件不会反向进入小说正式域。

## 6. 领域模型

### ComicProject

- `id`、`project_id`、`title`
- `source_chapter_ids`、`source_snapshot_sha256`
- `episode_target_count`、`episode_duration_seconds`
- `aspect_ratio`、`art_style`、`adaptation_mode`
- `narration_preference`、`author_requirements`
- `state`：draft / planning / outlined / producing / completed
- `season_revision`、`created_at`、`updated_at`

### ComicEpisode

- `id`、`comic_project_id`、`episode_number`、`title`
- `source_chapter_ids`
- `outline_state`：candidate / approved
- `script_state`：empty / candidate / approved
- `outline_revision`、`script_revision`
- `created_at`、`updated_at`

### ComicVersion

- `target_kind`：season / episode_outline / episode_script
- `target_id`、`version_number`、`state`：candidate / approved / rejected
- `content_json`、`content_sha256`
- `source_snapshot_sha256`、`job_id`
- `created_at`、`reviewed_at`

版本只增不改。批准新版本会拒绝同目标的旧候选，但不删除历史。

### ComicScene

- `episode_id`、`scene_number`
- 场次结构字段与 `source_chapter_ids`
- `script_version_id`、`created_at`

只物化已批准剧本的场次；候选内容只存在版本和 Artifact 中。

## 7. AI 与批准边界

新增两个可恢复任务：

- `comic_season_plan`：生成季纲和全季分集候选。
- `comic_episode_script`：为一个已批准分集大纲生成完整剧本候选。

每次调用必须：

1. 先展示模型线路、外发内容类型、字符数、Token 和费用估算。
2. 作者确认外发范围和费用上限。
3. 保存冻结上下文 Artifact、prompt version、来源哈希和幂等键。
4. 结果经过 Pydantic 结构校验和来源 ID 白名单校验。
5. 模型失败、应用退出或重试时复用已付费 Artifact。
6. 候选未经批准不能物化剧集或场次。

小说原文始终标记为不可信资料，不能把其中的命令式文本当作系统指令。

## 8. 确定性审校

每集候选或已批准剧本提供无需额外模型费用的检查：

- 开场钩子、核心冲突、情绪兑现和结尾卡点是否存在
- 场次数、对白和可见动作是否为空
- 时长是否偏离目标
- 场次来源是否属于本改编项目
- 前后集人物、地点和关键道具是否存在明显断裂
- 单集新资产数量、特效和复杂场景是否过密
- 是否含 AI 生成内容标识和发布合规提示

检查结果是创作与制作提示，不替代平台审核或法律判断。

## 9. UI 方向

页面单一任务是“把一段小说推进到下一集已批准剧本”。视觉语言取自漫剧分镜接触表和场记板，而不是通用数据后台：

- 左侧为纵向剧集胶片轨，显示大纲/剧本批准状态。
- 中央是当前阶段画布：来源范围、季纲、分集大纲或完整剧本。
- 右侧为审校和制作资产抽屉，窄屏收为页内区块。
- 标志性元素是剧集轨上的双道批准印记，而不是装饰性图表。
- 沿用墨舟纸张与墨色基底，新增分镜蓝 `#315C6B`、批准青 `#2F7463`、候选紫 `#76506E`、警示琥珀 `#B26A2D`。
- 普通文字不小于 14px，辅助文字不小于 12px；支持 1040px 和 760px 窗口、键盘焦点与 reduced motion。

## 10. 安全与合规

- 所有 API 输入使用白名单枚举、长度、数量和 UUID 校验；SQL 必须参数化。
- 原文、剧本、模型提示和 Artifact 不进入诊断包或普通日志。
- 导出文件名清理控制字符和路径字符；导出是内存只读生成。
- AI 生成内容在制作包内提供显式声明字段和元数据说明，不承诺代替平台最终标识工具。
- 项目只接受作者自有小说；若来源包含参考作品，继续受现有权利声明和原创性门禁约束。
- 不自动上传、发布、备案或断言内容合规。

## 11. MVP 不做

- 图片、分镜图、角色立绘和场景图生成
- 配音、音乐、字幕、口型和视频合成
- 平台账号、自动发布和数据回收
- 多人协作和云端项目
- 全书无人值守批量改编
- 用改编内容回写小说正文或正式事实
- 针对某一家图片/视频模型写死提示词

## 12. 测试与成功标准

- 数据：迁移、归档、恢复副本、外键重映射和旧格式升级通过。
- 任务：预览零调用、确认/费用门、幂等、取消、重试和 Artifact 恢复通过。
- 批准：季纲、分集大纲和剧本每级都不能绕过；旧 revision 被阻断。
- 来源：跨项目、删除、重复或不连续章节被拒绝；模型伪造来源被拒绝。
- 导出：只有已批准剧集进入制作包；JSON/Markdown/DOCX 内容、顺序和 SHA-256 稳定。
- UI：作者能创建项目、生成季纲、确认大纲、生成并批准一集剧本、查看审校和导出。
- 质量门：完整 lint、类型检查、测试、规模基准、生产构建、sidecar 和 Tauri 检查通过；浏览器控制台零 warning/error。

## 13. 开放问题

无阻断问题。图片/视频生产链在 MVP 文字制作包被真实作者验证后另立 PRD。
