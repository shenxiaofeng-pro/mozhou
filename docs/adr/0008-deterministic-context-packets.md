# ADR 0008：确定性 ContextPacket 与分层召回

> 状态：已接受
> 日期：2026-08-10

## 背景

长篇网文的连续性不能依靠把整个作品塞进模型，也不能只取最早或最近的固定数量记录。历史重生和都市重生还同时包含原始历史、小说分歧后时间线、主角未来知识和作者确认的现实资料。如果生成前的选择不可解释、不可重放，就无法证明模型当时真正读到了什么。

## 决定

1. 章纲和正文 Job 只消费编译后的 `ContextPacket`，不在 worker 执行时重新扫描可变作品数据。
2. ContextPacket 记录章节 revision、任务类型、编译器版本、Token 预算、源指纹、内容哈希、入选/未选原因和可回链字符范围。同一数据、revision、编译器版本和预算必须得到同一内容和语义 ID。
3. 上下文按硬约束、正式事实、当前状态、近期正文、远期摘要、双时间线、现实资料和已批准蓝图分层预算。后续层预算在前置层选择时保留，最后再按全局优先级利用余额。
4. 当前章纲、作者本次意图、命中当前参与实体的最新正式事实、实体状态、开放伏笔与仍有效的未来知识是硬约束。硬约束超预算时显式标记 overflow，不允许静默丢弃。
5. 原始历史仅作对照，不覆盖小说分歧后时间线；已失效的未来知识、已回收伏笔和未确认现实资料必须带原因排除。
6. 作者的“本章固定/本章排除”是带 revision 的章节级指令。排除不能覆盖硬约束或来源状态门禁，且 UI 必须允许撤销已生效的固定。
7. 预览时持久化不可变快照，提交时重编译并比对；如果作品已变更则拒绝建 Job。Job 同时保存 ContextPacket Artifact，项目归档恢复后即使派生快照表不在，仍能通过完整性校验的 Artifact 安全重放。
8. MVP 使用 SQLite 查询和确定性规则编译，不把向量数据库作为连续性正确性前置。只有当标注评测证明规则召回不足时，才在后续 ADR 中引入语义召回。

## 结果

- 外发预览与真实 provider 输入一致，作者可看到“为什么选/为什么不选”。
- 30 万字已有作品仍在固定 Token 预算下编译，历史摘要保留章节和字符范围证据。
- Job 提交后新增人物或事实不会漂移已冻结的模型输入。
- 编译器规则变更必须提升版本并重跑标注黄金集。

## 回滚边界

可将新编译器版本回退为旧规则，但已经提交的 Job 仍消费其冻结 Artifact。回滚不得改写旧 ContextPacket、绕过哈希校验、将参考原文直接交给正文 Agent，或将硬约束超预算伪装成正常编译。
