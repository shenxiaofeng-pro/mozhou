# ADR 0017：不可变剧情沙盘与候选隔离

## 状态

已接受。

## 背景

M12 需要把角色/势力推演、变量注入、分支比较和角色采访引入创作工作台，同时避免把推演伪装成历史事实、让沙盘状态污染正式作品，或因参考 MiroFish 的产品思路而引入 AGPL 源码及外部云依赖。

## 决策

1. 沙盘采用独立的清洁实现，不复制 MiroFish 的源码、Prompt、资产或数据结构，不引入 AGPL 依赖、Zep Cloud、Twitter/Reddit 动作模型或外部社交数据。
2. 每次推演先从当前项目的正式事实、原始/小说双时间线、已确认现实资料和作品年代地点创建不可变 `SandboxSnapshot`。快照保存内容哈希，运行前后均校验，项目后续变化不会反向改写既有推演。
3. `mozhou-sandbox-v1` 首版是本地确定性规则引擎，不调用模型。固定支持历史势力与都市商战模板、5 至 20 个角色/势力、3 至 10 轮和 5 至 200 次行动预算；同一快照与种子可重放。
4. 行动必须同时满足角色能力、已知信息、位置、目标和资源约束。每轮持久化行动、结果、假设、证据、状态哈希和剩余预算，允许逐轮运行、连续运行、取消及重启恢复。
5. 变量分支各自保存独立状态，不写回快照，也不互相读取。分支比较必须属于同一项目，并明确标注是否来自同一快照。
6. 报告中的每条结论都包含假设、证据、置信度、影响链和反例。采访只能使用该角色在快照和已完成轮次内可知的信息；所有输出持续标注为创作推演，不是历史或现实真相。
7. 沙盘产物只能创建 `chapter_outline` 或 `fact_change` 候选。作者批准只改变候选自身状态，不能写入章节正文、正式事实、双时间线或其他创作账本；正式应用仍须经过对应模块既有的批准流程。
8. 沙盘数据默认不进入项目归档。项目归档继续保持当前稳定契约；未来若需要迁移沙盘，新增显式沙盘导出格式，不静默扩大普通归档的数据范围。

## 结果

- 作者可以用同一正式世界状态探索多个假设，并在不污染作品的前提下比较后果。
- 首版运行成本有确定上限且不产生模型费用，失败或退出后已完成轮次仍可恢复。
- 推演结论可追溯、可质疑、可重放，不会冒充 Canon 或现实预测。
- 沙盘与正文、正式事实、双时间线保持数据库和 API 双重隔离。

## 回滚边界

沙盘是独立 P1 模块，可以整体隐藏路由和入口；删除 v17 表必须通过后续显式迁移。回滚不能把沙盘候选自动转成正文或 Canon，也不能为兼容旧实现而引入 MiroFish 源码或外部云服务。
