# ADR 0015：脱敏诊断与签名发布证据

## 状态

已接受。

## 背景

M10 要求作者能理解低磁盘、SQLite busy、损坏库和升级失败，同时又不能让日志或求助材料泄漏小说正文、参考原文、文件路径和 API Key。公开仓库还需要可验证的 macOS/Windows 构建来源、许可证清单和签名门。

## 决策

1. 本地事件日志只接受固定字段：时间、级别、事件、随机请求 ID、HTTP 方法、路由模板、状态码、耗时和固定错误码。禁止传入请求体、查询串、真实资源 ID和任意异常文本。
2. 日志限制为当前和上一份各 2 MiB；日志写入失败不能反向导致创作操作失败。
3. 一键诊断包只包含版本、平台、架构、数据库大小/结构版本/`quick_check`、磁盘空间、数量统计和最近 200 条脱敏事件；默认不附带数据库、归档、作品名、正文、参考资料、路径、Prompt、密钥或会话令牌。
4. SQLite busy 返回可重试的 503；磁盘写满和只读目录返回 507；错误响应不回显底层 SQL 或文件路径。桌面启动前先做数据库预检，损坏、版本过新、备份或迁移失败都只通过白名单错误码跨进程传递。
5. 每次发布从锁定的 npm、Python 和 Rust 依赖生成 CycloneDX SBOM、NOTICE、SHA-256 和含源提交/工具链的发布记录。AGPL、GPL-3、SSPL 和 BUSL 依赖默认阻断，除非另立 ADR 明确处置。
6. 标签发布不允许静默降级为无签名构建。macOS 必须使用 Developer ID 并公证/装订；Windows 必须使用 Azure Artifact Signing/Authenticode；缺任一凭据时发布候选流水线失败。
7. 公开仓库使用 GitHub OIDC 生成构建来源和 SBOM 证明。公开可见性不改变产品代码的授权状态，也不改变 MiroFish 清洁实现边界。

## 结果

- 作者可安全导出足以定位运行故障的材料，无需上传自己的小说或数据库。
- 损坏库和升级失败不会只表现为白屏或“服务超时”，并且不会暴露可被篡改状态文件注入的文本。
- PR 构建可以继续使用 ad-hoc/无发布证书的验证包；只有严格标签流水线产物可进入封闭测试发布清单。
- Developer ID、Apple 公证和 Azure 签名凭据是外部发布依赖，不能由仓库代码替代。
