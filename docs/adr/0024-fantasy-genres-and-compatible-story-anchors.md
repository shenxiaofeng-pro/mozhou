# ADR 0024：四题材白名单与兼容故事锚点

## 状态

已接受。

## 背景

产品原先只把历史重生和都市重生作为正式题材，数据库与归档使用 `genre`、`rebirth_year` 和 `rebirth_location` 表达项目锚点。增加东方玄幻与西方奇幻时，如果直接改列名或拆表，会迫使全部旧库、归档、任务快照和上下文产物迁移；如果只在创建页增加选项，AI、审校、时间线、资料研究和剧情沙盘又会继续套用重生逻辑。

## 决定

1. `Genre` 采用四值白名单：`historical_rebirth`、`urban_rebirth`、`eastern_fantasy`、`western_fantasy`。未知值继续由 Pydantic 和 TypeScript 契约拒绝，不接受任意字符串扩展。
2. 保留数据库、API 与 v10 归档的 `rebirth_year/rebirth_location` 物理字段。历史/都市重生把它们解释为重生年份/地点，东方/西方幻想把它们解释为故事纪年/起始地域；本次不提升 schema 或归档版本。
3. 题材显示、默认锚点和文案由共享 helper 集中定义。AI Prompt、假模型、ContextPacket 和审校先读取 `genre` 再分派规则；幻想题材默认非重生，不得因兼容字段名擅自加入前世记忆。
4. 东方玄幻检查修炼来源、境界边界、突破条件、资源循环和力量代价；西方奇幻检查魔法来源、施法代价、种族/阵营、地理文化和资源成本。重生题材继续检查年代、未来知识和分歧因果。
5. 起航模板、资料研究语境和剧情沙盘模板按题材提供并过滤。所有 AI 与沙盘结果继续受现有外发确认、费用门、规则裁决和候选批准边界约束。
6. 本批次不建立独立修炼/魔法 schema。作者先使用整书蓝图、资料卡、正式事实、资源账本和世界机制审校；只有真实作者验证通用模型不足后，才新增专用领域迁移。

## 结果

旧项目和旧归档无需迁移即可继续打开，新题材也能完整经过创建、导入、生成、审校、研究、沙盘和归档流程。兼容字段名属于存储实现，不再泄漏为幻想题材的界面或模型语义。

## 回滚边界

可以隐藏新题材的创建入口、起航模板或专属沙盘模板，但必须保留四值枚举读取能力，避免已创建项目无法打开或恢复。不得通过回滚删除幻想项目；若未来引入专用力量体系表，应以附加迁移和兼容读取实现。
