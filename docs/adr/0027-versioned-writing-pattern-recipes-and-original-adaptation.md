# ADR 0027：版本化写作模式配方与原创迁移门禁

## 状态

已接受（2026-09-12）

## 背景

CraftPattern v2 已能把长篇参考作品拆成带来源锚点的抽象技法资产，但资产本身不是可直接执行的创作指令。若把多张卡片直接拼进提示词，作者无法表达不同作品分别用于开篇、升级、反例或避让，也无法稳定处理冲突；更严重的是，来源原文、专名、人物组合或独特场景顺序可能越过边界进入规划和正文。

产品目标是“人工选题、AI 主写、人工调整”。参考作品只能帮助作者学习抽象的时代功能、核心欲望、冲突因果、资源体系、关键场景功能顺序和结局功能，不能形成换名复刻。AI 必须先给出隔离候选，作者采用后还要对实际整书蓝图执行与版本绑定的原创性检查。

## 决定

1. 全局 `WritingPatternRecipe` 与 `RecipeSource` 使用不可变版本；项目只保存指向特定版本的快照和当前 `WritingPatternProfile`。来源项明确记录权重、适用阶段、用途以及 preserve / transform / avoid 策略，冲突由作者逐项决定。
2. 配方编译完全确定性，输出紧凑的 model-safe profile、禁止复刻规则、来源可用性和内容指纹。相同输入必须得到相同指纹；修改全局配方只能创建新版本，不能影响既有项目。
3. 原创迁移是有预检的异步 AI 任务。外发前展示模型、数据范围、Token、费用和是否传到外部服务；未知外部价格、未确认外发、费用上限不足或预检后依赖漂移均在模型调用前阻断。
4. 模型边界只允许已确认选题、model-safe profile、作者意图、当前蓝图和字段锁。参考标题、作品标识、证据、原文、来源专名和内部谱系不进入任务上下文；嵌套创作内容一律按不可信数据处理，不能成为提示词指令。
5. 每次任务必须产生恰好三套隔离候选，服务端根据实际字段和场景结构验证两两差异，不能信任模型自报的差异标签。人物关系默认重构，锁定字段保持原值。候选编辑只增加不可变版本，并使用事务化 revision/content-hash 比较交换。
6. 作者采用候选后才写入 `BookBlueprint`，且状态为“待原创性检查”。门禁检查实际当前蓝图 revision，而不是只检查最初候选；蓝图、选题、配方、来源可用性或阈值变化会使旧报告失效，作者可在调整后重新运行检查。
7. 原创性门禁同时检查来源专名、人物关系功能组合、关键场景顺序、冲突—资源因果组合和多作品聚合风险。报告只保存固定摘要与二次哈希，不保存被命中的来源词面。低风险直接通过；中风险必须先查看报告再确认；高风险不可确认跳过。
8. 一旦项目采用过模式迁移蓝图，归档当前 profile、删除参考原文、排队后修改依赖或从旧的同步/示范/导演入口生成，都不能绕过当前门禁。所有规划、章纲、正文、改写和沙盘入口必须在调用 Adapter 与应用结果前重新验证同一中央门禁。
9. 项目归档保存配方、profile、迁移任务、三候选版本、采用记录和原创性报告的完整闭包；参考原文仍只在作者明确选择包含原文的完整归档时导出。旧版 v1 reference application 保持只读兼容，不重新开放为写作入口。

## 结果

- 作者可把多本作品的不同阶段技法组合为可解释、可复用的写作配方，而不是无序拼接摘要。
- AI 可以承担整书原创迁移的主要起草工作，但所有结果停留在候选区，最终采用和中风险确认仍由作者决定。
- 原创性检查绑定真实蓝图和依赖状态，拆分卡片、归档 profile、删除原文或复用旧任务都不能规避门禁。
- 安全性和可追溯性提高的代价是任务状态、版本谱系、归档闭包和旧入口兼容测试更复杂。

## 回滚边界

可关闭 AI 原创迁移 Adapter 和新建配方入口，但不得删除已生成的配方版本、项目快照、候选版本、采用记录或报告。已采用过模式迁移的项目不能通过关闭页面功能恢复为无门禁状态；需要继续创作时仍必须有与当前蓝图匹配的通过报告。数据库仅通过后续追加迁移演进，不回退或覆盖 schema v27 的领域表及 schema v28 的专用任务路由；旧版参考应用继续只读。
