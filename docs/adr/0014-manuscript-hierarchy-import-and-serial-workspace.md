# ADR 0014：无损稿件接续、稳定目录与本地连载工作台

- 状态：已接受
- 日期：2026-08-11
- 关联：PLAN.md M9，ADR 0002、0003、0008、0013

## 背景

作者常带着已有 TXT 或 Markdown 旧稿进入工作台。直接导入会同时带来编码误判、卷章标题误识别、超长章节、半成品项目和既有正文无法追溯等风险。进入工作台后，卷、章、场景还需要频繁调整；如果用序号充当标识，移动会破坏版本、事实和伏笔引用。连载期也需要知道当天新增、存稿、审校和定稿状态，并在长篇正文中快速定位内容。

## 决定

1. 稿件导入分为“只读预览”和“确认写入”两个阶段。预览检测 UTF-8、UTF-8 BOM 或 GB18030，识别书名、卷、章、章前散文和置信度，允许作者校正标题；预览期间不创建任何数据库记录。
2. TXT 与 Markdown 标题规则保持保守。无标题稿件作为单章低置信度候选；空章、低置信度、章前散文和超长章必须显式确认。超过单章上限的正文按段落安全拆分，相邻分段拼接后必须与原文逐字符一致。
3. 确认导入在一个 SQLite 事务内创建作品、稳定卷 ID、稳定章 ID和每章初始版本；任意章节或版本写入失败会回滚整个作品。
4. 正文 Markdown 导出与项目 JSON 归档分离。正文导出只含书名、卷、章和 UTF-8 正文；归档继续承担应用状态、版本、任务、资料与恢复职责。
5. 卷、章和场景使用稳定 UUID 与独立 `sort_key`。移动只改变父级和顺序，不改变节点 ID；重命名、移动和删除使用 revision 乐观并发门。
6. 删除采用软删除并先返回影响摘要。最后一卷和最后一章禁止删除；版本、正式事实、审校和生成引用不级联清除。最近一次目录操作可在无后续冲突时撤销，恢复原 ID 与子树。
7. 日更实际字符由当天非候选章节版本相对上一版本的正向增量计算，不把 AI 候选或删字伪装成新增。日目标带 revision；看板明确区分存稿、待审校、审校中、定稿和可发布。
8. 本地搜索只返回有上限的片段，覆盖作品、章节正文、人物、资源和伏笔；不把整本正文复制到常驻前端状态。`Cmd/Ctrl+K` 打开搜索，`Cmd/Ctrl+S` 保存，`Cmd/Ctrl+Shift+F` 切换专注模式，`Alt+Up/Down` 安全切章。
9. 项目归档升级为 v6，保存并重映射卷、章、场景、目录事件和日更目标；v1 至 v5 继续自动升级导入。

## 结果

- 好处：旧稿可以在不污染数据库的前提下先校正；目录重组不破坏长篇引用；删除可解释且可恢复；作者能在一个入口看到日更状态并搜索全书。
- 代价：保守标题规则会把少量非标准标题留给作者校正；软删除会保留少量本地数据；“今日新增”依赖只增章节版本而不是键盘击键日志。
- 隐私：解析、搜索、看板和 Markdown 导出全部在本机执行，不调用模型，不产生费用，也不发送正文。

## 回滚边界

可以隐藏目录管理、连载台和搜索入口，也可以回退标题识别规则；已写入的稳定 ID、软删除记录、目录事件、章节版本和 v6 归档必须继续可读。不得回退为预览即写库、移动时更换 ID、物理级联删除或用 AI 候选计算日更实际字数。
