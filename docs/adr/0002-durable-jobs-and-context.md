# ADR 0002：持久化任务运行时与版本化上下文

> 状态：已接受
> 日期：2026-08-09

## 背景

长篇拆书会产生数十次模型调用，真实写章也可能因断网、限流或应用退出中断。当前同步请求不能保留已付费块，也不能可靠恢复。长篇创作还要求明确说明每次生成使用了哪些事实和资料。

## 决定

1. 所有长 AI 工作统一映射为 Job、Attempt、Chunk、Artifact 和 Event。
2. 任务状态和结果持久化到 SQLite，使用租约、心跳和幂等键防止重复副作用。
3. sidecar 重启后只恢复可安全重放的阶段；已成功 Artifact 不重复调用。
4. 生成前构建版本化 ContextPacket，记录内容哈希、编译器版本、预算、来源与入选原因。
5. 正文 Agent 只能消费 ContextPacket，不能自行扫描整库或参考原文。
6. MVP 使用 sidecar 内单机 worker，不引入 Redis、云队列或分布式协调。

## 结果

- 写章、拆书、审校和后续沙盘共用任务语义。
- 取消、重试和恢复可以按块发生，费用与失败位置可解释。
- 上下文选择可以独立评测和重放。
- 数据库写事务必须保持短小，worker 不在事务中等待模型。

## 回滚边界

迁移期间旧同步接口可保留一版开发兼容，但产品 UI 只走任务接口。关闭 worker 不删除 Job 或 Artifact；不得用丢弃历史结果作为回滚方式。
