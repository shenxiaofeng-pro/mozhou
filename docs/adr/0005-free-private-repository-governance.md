# ADR 0005：免费私有仓库的阶段性治理控制

- 状态：已接受
- 日期：2026-08-09

## 背景

MVP 已确定闭源私有测试。GitHub API 对当前个人免费账户的私有仓库 Branch Protection 和 Repository Ruleset 均返回 HTTP 403，要求升级 GitHub Pro 或改为公开仓库。公开会违反闭源决策，而单人内测阶段暂不购买 Pro。

## 决策

1. 保持仓库私有，不为获得免费保护而公开源码。
2. 使用版本化 `.githooks/pre-push` 阻止本机直接更新或删除远端 `main`。
3. `pnpm install` 自动配置 `core.hooksPath=.githooks`，同时保留显式安装命令。
4. 所有变更继续使用短生命周期分支和 Pull Request；只有 macOS、Windows、security 三项 CI 全绿后才能合入。
5. 当前控制是产品负责人明确接受的 M0 阶段性例外，不等同于服务端分支保护。
6. 增加协作者、进入外部测试或发布准备前，必须重新评估 GitHub Pro、组织 Team 或其他支持私有保护分支的平台。

## 后果

- 单机常规工作流会在推送前阻断误操作，规则随仓库版本传播并有自动化测试。
- 拥有写权限的人仍可用 `--no-verify`、更改 hook 或其他客户端绕过，所以无法防御恶意或刻意绕过。
- M0 可以按已确认的阶段性验收口径结束，但该风险必须保留在进度和发布门中，不能描述为服务端已保护。
