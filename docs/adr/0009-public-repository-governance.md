# ADR 0009：公开仓库与服务端分支保护

> 状态：已接受
> 日期：2026-08-10
> 替代：ADR 0005 的“免费私有仓库阶段性治理”决策

## 背景

个人 GitHub Free 私有仓库无法启用所需的服务端分支保护，且本计费周期的 GitHub Actions 免费额度已用尽。产品负责人已将仓库改为公开，并要求继续实施 PLAN.md。

## 决定

1. `shenxiaofeng-pro/mozhou` 保持公开，使用 GitHub 托管的标准 macOS、Windows 和 Linux/security 运行器执行发布门。
2. `main` 启用服务端分支保护：禁止强制推送和删除，合并前必须通过 macOS、Windows 和 security 三项检查。
3. 版本化 pre-push hook 与仓库守卫继续保留，作为本机误操作和数据/密钥入库的第一层防线。
4. 公开可见性不改变清洁实现边界：不复制 MiroFish 源码、提示词或资产，不将作者原稿、参考原文、本地数据库和凭据提交到仓库。
5. 产品仍是本地优先的 macOS 封闭测试版；仓库公开不代表已经达到 MVP 发布门。

## 结果

- M4 及后续 PR 可在不升级 GitHub Pro 的情况下恢复完整远端验证。
- 服务端规则代替 ADR 0005 中可被绕过的本地约束，但本地守卫仍作为纵深防护。
- 后续变更必须更严格审查测试夹具、日志、归档和生成产物，因为任何提交都公开可读。

## 回滚边界

如果仓库重新转为私有，必须在可见性变更前先确认 Actions 计费/自托管运行器和分支保护方案，不得再无声退回仅依赖本地 hook 的状态。
