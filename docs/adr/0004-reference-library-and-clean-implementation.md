# ADR 0004：全局拆书库、原创性门禁与清洁实现

> 状态：已接受  
> 日期：2026-08-09

## 背景

作者需要一次导入和分析多部长篇参考作品，并把抽象结构复用到不同创作项目。直接把参考原文提供给正文 Agent 会造成隐私、版权和仿写风险。MiroFish 的角色与势力推演能力有参考价值，但其 AGPL-3.0 许可不适合直接合并到闭源 MVP。

## 决定

1. 参考原文属于全局本地拆书库，不复制到每个项目。
2. 项目只引用模式卡，并保存已选择抽象维度的不可变应用快照。
3. 参考原文、证据、抽象模式、原创蓝图、正式事实使用不同模型和仓储接口。
4. 正文 ContextPacket 只能包含已应用、已通过门禁的摘要与可迁移逻辑。
5. 蓝图进入规划或写章前必须检查短语、专名、人物组合、关键节拍序列和多维组合风险。
6. 高风险结果必须调整或重生成后重新检测，不能通过二次确认直接绕过。
7. 剧情沙盘采用小说行动模型独立实现，不复制 MiroFish 源码、提示词、资产，不引入 Zep Cloud 或社交媒体动作模型。

## 结果

- 同一拆书资产可以跨项目复用，同时保持来源谱系。
- 删除全局原文后，已应用抽象快照仍可解释，但不能恢复原文分析能力。
- 项目归档默认携带应用快照；只有显式选择才携带关联参考资产。
- 原创性报告是风险提示和产品门禁，不声称法律上的侵权或不侵权结论。

## 回滚边界

全局迁移失败时保留旧项目内参考表只读一版，并从升级前备份恢复。任何回滚都不能让正文 Agent 获得参考原文查询权限。
