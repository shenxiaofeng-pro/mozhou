# ADR 0026：可审计的长篇写作模式资产

## 状态

已接受（2026-09-11）

## 背景

旧版拆书模式卡以一次跨书综合结果为中心，不能自然表达单本长篇在不同阶段的技法变化，也缺少足够稳定的来源证据、版本谱系和提交前费用边界。它还曾直接形成可进入写作上下文的参考应用，不适合作为后续“多书配方 → 原创迁移 → 作者确认”的安全输入。

## 决定

1. CraftPattern v2 使用三级只增资产：`stage` 阶段卡、`book_evolution` 单书演变卡和 `fusion_material` 多书融合素材。单书分析只接受同一本作品；融合必须覆盖至少两本不同作品。
2. 每项技法属于 15 个受控维度之一，保存可迁移规则、改编风险、置信度，以及经服务端验证的作品、区段、章节/阶段、绝对字符范围、摘要和证据哈希。参考原文不写入资产正文，也不进入写作上下文。
3. 任务提交前生成绑定来源内容、模型/价格、缓存状态、选择范围和作者重点的预检哈希。未命中的外发、未知价格和费用上限必须显式确认；预检后发生来源、价格或缓存漂移时拒绝提交。
4. 分析缓存、任务产物和资产以内容指纹幂等复用。任务执行前再次验证承诺的缓存命中和来源；参考原文在执行期间被清理时停止后续调用且不落不完整资产。
5. 全局资产不可变，项目仅保存带乐观 revision 的 `active` / `archived` 关联。删除参考原文后，已验证的抽象资产及其父谱系仍可浏览、融合和跨项目复用。
6. 项目归档 v13 保存项目所需资产的完整父闭包并校验哈希、类型、来源和证据；恢复中的未完成或失败任务不会自动重试，也不能绕过新的预检和费用确认。
7. 旧版 v1 卡片、应用和历史报告仅供读取及生命周期管理；禁止新建、编辑、重新检查或重新应用。CraftPattern v2 在 M31 配方工作流完成前不得进入章纲、正文、导演、沙盘或其他写作上下文。

## 结果

- 300 万字作品可按约 50 万字阶段形成多张独立资产，并汇总为单书演变；作者不再需要伪造第二本参考书。
- 多书借鉴的输入从“原文/一次性摘要”变为可追溯、不可变、可组合的抽象技法资产，为后续配方和原创性检查提供稳定边界。
- 预检和执行时的双重校验避免缓存、价格、来源变化造成意外外发或费用；代价是领域模型、归档闭包和恢复测试更复杂。
- 全局资产与项目生命周期分离，允许一次拆解、多项目复用，同时不会因解除关联或清理原文破坏历史成果。

## 回滚边界

可关闭 CraftPattern v2 的分析、融合和复用入口，但不得删除既有资产、父谱系、证据或项目关联。v1 保持只读兼容，不能作为功能回滚重新开放写入或重新进入 AI 上下文。数据库只通过后续追加迁移演进，不回退 schema v25；归档继续接受 v13 及更早版本并保持哈希校验。
