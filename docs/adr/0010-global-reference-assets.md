# ADR 0010：全局参考资产、项目关联与归档边界

> 状态：已接受  
> 日期：2026-08-10

## 背景

旧实现把参考作品直接挂在 `project_id` 下。同一本长篇用于两部新书时必须重复导入和分析；删除或归档项目也会把参考原文与项目生命周期绑死，无法形成作者级资产库。

## 决定

1. 参考作品与原文区段属于全局作者资产，项目通过 `project_reference_works` 多对多关联，不复制原文。
2. v9 迁移保留旧作品、区段 ID、原文和项目可达性；内容哈希、编码状态和更新时间在迁移时补齐。
3. 相同内容只标记重复候选，不自动合并；权利基础仍属于每次导入的独立声明。
4. 普通 Workspace、全局列表和日志只返回区段元数据，不返回参考原文；分析处理器按已关联项目在受控仓储方法内读取原文。
5. 项目归档 v2 默认不带全局参考原文，只保存可解释的抽象蓝图；显式选择“包含参考资产”时才打包关联作品和区段。导入后创建新的全局资产副本并关联恢复项目。
6. v1 项目内参考作品归档继续可读，导入时转换成 v2 全局资产结构。

## 结果

- 同一参考作品可以被多部作品复用，解除关联不会删除全局原文。
- 默认项目备份更小，也不会在作者未明确选择时携带参考小说原文。
- 全量归档仍能离线恢复，但恢复的是独立资产副本，不会与现有全局资产静默合并。

## 回滚边界

旧 `project_id` 所有权列不会恢复。若全局工作台需降级，可隐藏跨项目入口，但必须继续使用关联表，避免重新引入原文复制和级联删除。
