# 墨舟

墨舟是一个本地优先的中文长篇小说工作台，首发聚焦历史重生与都市重生。当前仓库已经跑通安全写作与连载控制闭环：创建作品、编辑章节、自动保存、生成隔离候选稿、审校定稿、候选事实审核，以及由作者明确确认后写入正式事实、小说时间线和伏笔账本。

> 当前实施以 [PLAN.md](PLAN.md) 为冻结范围，以 [PROGRESS.md](PROGRESS.md) 记录验证进度。目标、真实能力和历史规划分别见 [PRD](docs/product/prd.md)、[能力状态矩阵](docs/product/capability-status.md) 和 [早期开发计划](docs/product/development-plan.md)；协作与协议冻结规则见 [贡献约定](CONTRIBUTING.md) 和 [0.1.0 基线契约](docs/product/v0.1.0-baseline.md)。

## 当前能力

- 创建历史重生或都市重生项目，记录重生年份、地点、章节目标字数和安全存稿量。
- 使用本地作品书架列出、打开和继续已有作品；退出作品只返回书架，不再丢失重新打开入口。
- 使用 SQLite 在本机保存作品、章节、revision 和生成任务状态；数据位于固定的用户应用数据目录，不再随启动目录变化。
- 首次升级会以 SQLite 一致性快照无损复制旧 `.mozhou-data` 数据库并保留原件；schema 升级前自动做完整性检查和版本化备份，损坏库或未来版本库不会被静默覆盖。
- 从作品书架导出完整 `.mozhou.json` 项目归档，覆盖正文、设定、生成记录和拆书原文；归档带独立格式版本与 SHA-256 完整性校验。
- 从归档或压缩恢复点恢复时始终创建新项目副本，并重映射全部主键、外键和模式卡引用，不覆盖当前作品；首次启动尚无作品时也可直接导入。
- 为每部作品创建带备注的压缩恢复点，在书架内查看并恢复；恢复点元数据与快照正文分离读取，归档不会递归包含恢复点。
- 700ms 串行自动保存，切章、进入拆书库或退出作品前强制落盘；保存失败时保留编辑器与本地草稿，使用乐观 revision 防止旧内容静默覆盖新内容。
- 编辑并持久化读者承诺、开篇钩子、章节状态变化、情绪回报和章尾悬念；核心章纲未完成或未保存时不能进入生成上下文。
- 连续添加章节、切换编辑，并始终展示当前章节之后的未来三章滚动窗口。
- 横向查看连续三章的承诺、钩子、变化、回报和悬念，提示重复节拍。
- 自动生成断更恢复卡，汇总上次进度、下一章入口、开放伏笔、人物/资源状态和待处理审核。
- 运行确定性连续性检查，提示未来知识待复核、伏笔逾期、节奏缺口、重复节拍、实体状态缺失和现实资料年代覆盖问题。
- 使用 `待写 → 草稿 → 审校中 → 已定稿` 状态机；定稿正文和章纲默认锁定，可显式重新打开。
- 接入 OpenAI Responses API：AI 可设计结构化本章章纲，也可基于已保存章纲生成完整章节候选稿。
- 多本长篇拆书采用可恢复的 5 万字 Map、单书 Reduce、跨书 Fusion 后台任务；失败重试会复用已完成块，页面可查看进度、取消后续调用并从失败块继续。
- API Key 可通过环境变量提供，也可在工作台临时配置；临时密钥只保存在本地 API 进程内存中，不写入项目或数据库。
- 保留可重放假模型，供离线演示和无网络自动化测试使用。
- 候选稿与正文隔离；只有作者点击“采用”后才会经过 revision 门禁写入。
- 定稿后提取“状态变化/开放伏笔”候选清单，支持部分接受或整批拒绝；模型不能直接修改正式事实。
- 维护可编辑的人物与资源账本，记录定位、欲望/用途、当前状态和关系备注。
- 维护伏笔生命周期：人工埋设或由已确认的开放线索自动创建，支持回收、放弃和重新打开，并保留来源章节。
- 并列维护原始时间线和小说时间线：现实/历史事件人工录入，小说变化只从作者确认的事实落轨。
- 维护带年份、来源与置信度的未来知识；小说分歧只触发“待复核”，由作者确认仍有效或正式失效。
- 维护带类型、来源、适用年代和可信度的现实资料卡；只有作者确认后才标记为现实锚点。
- 导入多本作者自有、已授权或公版 TXT/Markdown 小说；每本默认按 50 万字并优先在章节边界切成独立分析区段，300 万字可形成 6 段。
- 跨书选择区段并由 AI 分块萃取时代、核心欲望、冲突因果、资源体系、关键场景顺序和结局；六个维度保留来源区段回链，并给出共同规律、差异、人物关系重组和原创性风险。
- 独立“拆书库”管理页面，长期保存六维模式卡；作者可选择部分抽象维度、填写改编备注并明确确认后，应用为当前作品的参考结构蓝图。
- 已应用蓝图会进入后续章纲与正文 AI 的结构化上下文，但只包含摘要和可迁移逻辑，不包含参考原文、来源证据或未应用模式卡。
- 参考原文默认只在本地隔离库存储；只有作者明确勾选后，选中区段才按约 5 万字内部块发送给当前 AI，参考原文永不进入章纲或正文生成上下文。
- FastAPI 接口校验、参数化 SQL、受限本地 CORS，以及不回显内部异常的错误边界。
- React 工作台、章节脉搏和响应式三栏布局。

真实模型共创、离线假模型、正式事实、双时间线、未来知识、人物/资源/伏笔账本、现实资料卡、连续性检查、断更恢复卡，以及独立多书分段拆书库已进入最小可用阶段。点击 AI 写章时，只发送当前章纲、近期正文、正式事实、已确认资料和已应用抽象蓝图；点击拆书萃取时，只发送作者本次勾选并确认的参考区段。PDF 导入、整书总导演、多代理审校和阻断式相似度门禁仍在后续里程碑中。

## 本地运行

需要 Node.js、pnpm 10、Python 3.14、[uv](https://docs.astral.sh/uv/)；桌面壳还需要 Rust 和 Tauri 的系统依赖。

```bash
pnpm install
pnpm run backend:sync
pnpm run dev
```

如需启动真实 AI 共创，可通过环境变量提供密钥和模型：

```bash
OPENAI_API_KEY=你的密钥 MOZHOU_AI_MODEL=gpt-5.6 pnpm run dev
```

也可以启动后在工作台中临时输入 API Key；界面不会回显或持久化密钥。

默认数据库位置：

- macOS：`~/Library/Application Support/com.lingjing.mozhou/mozhou.db`
- Windows：`%LOCALAPPDATA%\Mozhou\mozhou.db`
- Linux：`$XDG_DATA_HOME/mozhou/mozhou.db`，未配置 XDG 时使用 `~/.local/share/mozhou/mozhou.db`

可用 `MOZHOU_DATA_DIR` 显式选择其他目录。显式选择时不会自动导入当前目录的旧库；如需指定旧库目录，可同时设置 `MOZHOU_LEGACY_DATA_DIR`。升级备份保存在数据库同级的 `backups/` 目录。

浏览器工作台默认位于 `http://127.0.0.1:5173`，本地 API 位于 `http://127.0.0.1:8765`。如果 5173 已被占用，Vite 会选择下一个可用端口。
浏览器开发脚本会显式启用无会话令牌兼容模式，并在 API 终端打印安全警告；该模式不用于桌面发行包。

桌面开发时直接启动 Tauri。命令会先生成当前平台的独立 FastAPI sidecar；桌面进程会自行选择动态本地端口、生成只存在内存中的 256-bit 启动会话令牌、等待健康检查，并在退出时回收 API：

```bash
pnpm run desktop:dev
```

## 验证

```bash
pnpm run verify
```

`verify` 会依次运行前后端 lint、严格类型检查、前端交互测试、后端测试、生产构建、独立 sidecar 构建与桌面 Rust 编译检查。当前为 28 项前端测试、101 项后端测试、4 项 Rust 测试和 10 项工程脚本测试，另已通过动态端口 sidecar 生命周期、数据库迁移、项目归档往返、恢复点、完整性/签名检查和 release 安装包验收。

桌面安装包构建：

```bash
pnpm run desktop:build
```

构建脚本会在系统临时 target 目录完成 release 签名和打包，再把安装器复制到 `artifacts/desktop/`。macOS 无发布证书时产出可本机测试的 ad-hoc 签名 DMG；配置 `APPLE_SIGNING_IDENTITY` 后，PyInstaller 与 Tauri 会共用同一证书并保持 Hardened Runtime，公证仍需要 Apple 发布凭据。Windows 需在 Windows 机器原生构建对应安装器。
