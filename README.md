# 墨舟

墨舟是一个本地优先的中文长篇小说工作台，正式支持历史重生、都市重生、东方玄幻与西方奇幻。当前仓库已经跑通安全写作与连载控制闭环：创建作品、编辑章节、自动保存、生成隔离候选稿、审校定稿、候选事实审核，以及由作者明确确认后写入正式事实、小说时间线和伏笔账本。

> 当前实施以 [PLAN.md](PLAN.md) 为冻结范围，以 [PROGRESS.md](PROGRESS.md) 记录验证进度。目标、真实能力和历史规划分别见 [PRD](docs/product/prd.md)、[AI 漫剧工作台 PRD](docs/product/ai-comic-drama-prd.md)、[能力状态矩阵](docs/product/capability-status.md) 和 [早期开发计划](docs/product/development-plan.md)；协作与协议冻结规则见 [贡献约定](CONTRIBUTING.md) 和 [0.1.0 基线契约](docs/product/v0.1.0-baseline.md)。

## 当前能力

- 创建历史重生、都市重生、东方玄幻或西方奇幻项目；重生题材记录重生年份/地点，幻想题材记录故事纪年/起始地域，并统一保存章节目标字数和安全存稿量。
- 使用本地作品书架列出、打开和继续已有作品；退出作品只返回书架，不再丢失重新打开入口。
- 使用 SQLite 在本机保存作品、章节、revision 和生成任务状态；数据位于固定的用户应用数据目录，不再随启动目录变化。
- 首次升级会以 SQLite 一致性快照无损复制旧 `.mozhou-data` 数据库并保留原件；schema 升级前自动做完整性检查和版本化备份，损坏库或未来版本库不会被静默覆盖。
- 从作品书架导出带 SHA-256 完整性校验的 `.mozhou.json` 项目归档；默认只带正文、设定、生成记录和已应用蓝图快照，作者也可显式导出包含关联参考小说与现实资料原文的完整归档。
- 从归档或压缩恢复点恢复时始终创建新项目副本，并重映射全部主键、外键和模式卡引用，不覆盖当前作品；首次启动尚无作品时也可直接导入。
- 为每部作品创建带备注的压缩恢复点，在书架内查看并恢复；恢复点元数据与快照正文分离读取，归档不会递归包含恢复点。
- 700ms 串行自动保存，切章、进入拆书库或退出作品前强制落盘；保存失败时保留编辑器与本地草稿，使用乐观 revision 防止旧内容静默覆盖新内容。
- 编辑并持久化读者承诺、开篇钩子、章节状态变化、情绪回报和章尾悬念；核心章纲未完成或未保存时不能进入生成上下文。
- 连续添加章节、切换编辑，并始终展示当前章节之后的未来三章滚动窗口。
- 从 TXT、Markdown、DOCX 或 EPUB 旧稿先预览编码与卷章树，再校正书名、卷名和章名；只有确认后才以单个事务创建作品和每章初始版本。
- 用稳定 ID 管理卷、章和场景，支持重命名、跨卷移动、顺序调整、删除影响预览和最近一步撤销；删除不会清除章节版本或故事引用。
- 将纯正文按 Markdown、DOCX 或 EPUB 导出，返回 SHA-256 与卷章统计；该入口与包含完整应用状态的 `.mozhou.json` 项目归档明确分离。
- 在连载台查看今日新增、日目标、总字数、存稿、待审校、定稿和可发布数量；42 天码字日历按正式章节版本计算每日净新增，未采用候选稿不计入统计。
- 用 revision、正文哈希与上下文锚定章节批注；改稿后仅在原文唯一出现时自动重定位，否则明确标记“待定位”。灵感箱只把想法标记为章纲/资料/人物候选用途，不直写正式域；人物关系与伏笔图谱只读取正式账本，并提供文本列表回退。
- 搜索全书章节正文、人物、资源、伏笔、灵感和批注；支持 `Cmd/Ctrl+S` 保存、`Cmd/Ctrl+K` 搜索、`Cmd/Ctrl+Shift+F` 专注模式、`Cmd/Ctrl+Shift+I` 灵感箱和 `Alt+Up/Down` 切章。
- 从作品书架执行数据库完整性、结构版本和磁盘空间只读体检，并一键导出不含书名、正文、资料原文、路径、Prompt 或密钥的脱敏诊断包。
- 使用历史重生、都市重生、现实锚点、东方玄幻或西方奇幻封测模板起航，并在作品书架查看连续十章里程碑、AI 候选采用率、正文保留率、人工调整分布、审校/恢复/成本指标；作者主观评分单独汇总，报告只在作者主动操作时脱敏导出。完整口径见 [封闭测试协议](docs/product/closed-beta-protocol.md)。
- 从正式事实、双时间线和已确认现实资料冻结剧情沙盘快照；规则模式可运行 5 至 20 方、3 至 10 轮的零费用确定性推演。可选 AI 模式逐轮展示外发范围、Token、线路和费用，确认后只让模型提出行动与候选后果；知识、位置、能力、资源和预算仍由本地规则裁决，非法提议自动拒绝并安全回退。两种模式的结果都只停留在候选区，不会改写正文、正式事实或时间线。
- 从同一作品的一段连续章节创建独立 AI 漫剧项目，先生成一季分集大纲候选，再由作者逐集批准大纲、生成带场次/动作/对白/旁白/画面重点的完整剧本候选并逐集批准；批准内容可审校、汇总角色/地点/服装/道具/特效资产，并导出 Markdown、JSON 或 DOCX 文字制作包。漫剧流程不改写小说原稿，不生成图片、音频或视频。
- SQLite busy、磁盘写满、只读目录、损坏库和升级失败都有可操作的安全提示；桌面启动状态只接受白名单错误码，不能通过本地状态文件注入任意文本。
- 横向查看连续三章的承诺、钩子、变化、回报和悬念，提示重复节拍。
- 自动生成断更恢复卡，汇总上次进度、下一章入口、开放伏笔、人物/资源状态和待处理审核。
- 运行确定性连续性检查，提示未来知识待复核、伏笔逾期、节奏缺口、重复节拍、实体状态缺失和现实资料年代覆盖问题。
- 使用 `待写 → 草稿 → 审校中 → 已定稿` 状态机；定稿正文和章纲默认锁定，可显式重新打开。
- 以“选题与整书 → 当前章计划 → AI 候选 → 审校定稿”四阶段组织连续创作；服务端根据作品真实状态给出唯一下一步主操作，刷新、前进后退和深链接都能恢复当前项目、章节与阶段。
- 接入 OpenAI Responses 与通用 OpenAI-compatible 网关：AI 可设计结构化本章章纲，也可基于已保存章纲生成完整章节候选稿。
- 长篇拆解采用可恢复的约 5 万字 Map、约 50 万字阶段归纳、单书演变和跨书融合后台任务；失败重试会复用已验证缓存，页面在提交前展示调用、命中、Token、线路和费用，并可查看进度、取消或恢复。
- 模型线路台可保存多个 provider profile、自定义 HTTPS 或回环 base URL、模型名和估价，并分别指定章纲、正文、拆书、审校、剧情沙盘与资料研究默认线路。
- macOS 桌面版把 API Key 保存在 Keychain；sidecar 只接收执行期内存副本，数据库、作品归档和 Web 前端都不能读回明文。浏览器开发降级只在当前页面内存保留，刷新即清除。
- 每次写章先展示数据类型、字符范围、预计 Token、目标线路和成本；作者再次确认后才创建任务。任务中心显示实际 Token、耗时、重试与估算费用。
- 保留脱敏 provider 回放夹具和可重放假模型，默认自动化测试全程不访问付费模型。
- 候选稿与正文隔离；只有作者点击“采用”后才会经过 revision 门禁写入。
- 定稿后以最终正文而非章纲提取九类带精确证据的 Canon 候选，覆盖人物状态、关系、资源、地点、知识、伏笔、能力成长与双时间线；作者可逐项编辑、接受或拒绝，模型不能直接修改正式事实。
- 从作者实际采用后的最终稿差异中生成压缩偏好候选；只有作者确认的抽象偏好进入后续 CreativeContext，大段历史 diff 和参考原文都不会进入写章上下文。事实回流后可生成未来 3 至 5 章滚动计划候选，仍需作者采用。
- 维护可编辑的人物与资源账本，记录定位、欲望/用途、当前状态和关系备注。
- 维护伏笔生命周期：人工埋设或由已确认的开放线索自动创建，支持回收、放弃和重新打开，并保留来源章节。
- 并列维护基线与小说时间线：重生题材录入现实/历史原始事件，幻想题材录入世界历史、纪年和规则底稿；小说变化只从作者确认的事实落轨。
- 维护带年份、来源与置信度的知识账本；重生题材用于未来记忆，幻想题材用于预言、推演或先验知识，世界线变化只触发“待复核”。
- 维护带类型、来源文件、页码/字符范围、日期、适用年代和可信度的资料卡；导入只生成候选，只有作者确认后才进入现实或世界规则锚点。
- 独立资料研究台可从已有资料或最多 20 万字粘贴文本建立来源快照；本地规则零费用提取，AI 模式必须再次确认外发范围与费用。所有结论都校验页码/字符范围和原文哈希，无证据或越界引用会被丢弃，冲突资料并列保留，逐条批准后才进入现实资料卡。
- 使用独立“全局资料码头”一次保存参考小说与现实资料，再按需装入不同作品或生成候选资料卡；解除项目关联不会删除全局原文。
- 导入多本作者自有、已授权或公版 TXT/Markdown/PDF/DOCX/EPUB；文本支持 UTF-8、UTF-8 BOM、GB18030 和可确认的低置信度预览。PDF、OOXML 与 EPUB 都经过大小、活动内容、外链和异常膨胀边界检查，ZIP 包额外拒绝路径穿越、加密与重复条目。
- 每本参考小说默认按 50 万字并优先在章节边界切成独立分析区段，300 万字可形成 6 段。
- 单书可独立拆解为阶段卡和整书演变卡；跨书选择不可变资产后形成融合素材。15 个受控维度覆盖时代、核心欲望、冲突因果、资源体系、关键场景顺序、结局、钩子、承诺兑现、情绪、信息揭示、伏笔、场景、POV、表达参数和力量成长。
- 独立“拆书库”管理页面按“来源 → 阶段卡 → 单书演变 → 融合素材”导航；每项技法都带合法作品/区段/章节或阶段、字符范围、摘要、证据哈希与置信度，可归档、恢复或跨项目装入。
- CraftPattern v2 只保存抽象规则和证据摘要，参考原文不会进入章纲或正文生成上下文；v2 资产需在“写作配方 → 原创迁移 → 作者确认”完成后才允许成为写作输入。旧版六维模式卡与蓝图内容保持只读，不能再新建应用或重跑检查，既有应用仍可暂停、归档或恢复。
- 在独立“写作配方”页面把 1–5 本作品的具体技法编成不可变版本：可设置来源权重、适用阶段以及保留、重构或避开，编译器会给出稳定规则、冲突和禁止复刻项；同一版本可跨项目装入，但每个项目只保存与已确认选题绑定的不可变快照。
- 基于当前选题和项目模式生成 3 套结构差异明确的原创迁移候选，人物关系默认重构；作者编辑并选择后仍须通过专名、短语、人物组合、关键节拍和多卡组合检查，再对实际整书蓝图 revision 复检。中风险先看报告并确认，高风险只能调整或重生成。
- 对已应用蓝图执行场景级语义与情节图检查：以候选场景节点、顺序、因果边、人物功能和跨书汇聚信号补充原有短语/专名门禁。报告只保存来源区段 ID、摘要和证据哈希，不复制命中原句；高风险不能绕过，中风险必须先查看情节图再确认。
- 参考原文默认只在本地隔离库存储；只有作者明确勾选后，选中区段才按约 5 万字内部块发送给当前 AI，参考原文永不进入章纲或正文生成上下文。
- FastAPI 接口校验、参数化 SQL、受限本地 CORS，以及不回显内部异常的错误边界。
- M28–M35 新入口有未知 JSON 字段拒绝、动态 SQL 审查白名单、上传/ZIP 边界、密钥/日志扫描、loopback 令牌和归档 fail-closed 回归门；范围与证据见 [M36 安全审查](docs/product/m36-security-review.md)。
- React 工作台、章节脉搏和响应式三栏布局。

真实模型共创、离线假模型、正式事实、双时间线、未来知识、人物/资源/伏笔账本、现实资料卡、连续性检查、断更恢复卡、全局资料码头、安全长篇拆解、版本化写作配方、原创迁移、阻断式原创性门禁、整书总导演、七维审校和定稿反馈闭环已进入最小可用阶段。总导演可从一句创意生成 2 至 3 个差异化开书候选，选择后形成可编辑、可锁定的整书蓝图、卷纲和未来 3 至 5 章；单章流水线按“上下文→章纲→写前审查→候选稿”运行，不会自动覆盖正文或正式事实。审校台把连续性、连载节奏、人物、现实性、重生逻辑、文风和格式问题统一为带正文或结构化证据的建议，支持单维重跑、部分应用、作者编辑和只增版本回滚。作者采用并定稿后，系统才生成 Canon 与写作偏好候选；确认结果进入下一章统一上下文，形成“AI 主写、人工调整、人工定稿、受控回流”的连续链路。点击 AI 写章时，只发送当前章纲、近期正文、正式事实、已确认资料、已确认抽象偏好，以及已通过实际蓝图原创性复检的抽象项目模式；任何参考原文、书名、证据摘录或未确认候选都不会进入正文上下文。点击长篇拆解时，只发送作者本次勾选并确认且未命中缓存的参考范围。

## 本地运行

需要 Node.js、pnpm 10、Python 3.14、[uv](https://docs.astral.sh/uv/)；桌面壳还需要 Rust 和 Tauri 的系统依赖。

```bash
pnpm install
pnpm run backend:sync
pnpm run dev
```

浏览器开发也可通过环境变量提供首条 OpenAI 线路的密钥和模型：

```bash
OPENAI_API_KEY=你的密钥 MOZHOU_AI_MODEL=gpt-5.6 pnpm run dev
```

也可以启动后在“模型线路台”配置多条 OpenAI-compatible 线路。桌面版会把密钥放入系统凭据库；浏览器开发只保留当前页面会话，界面都不会回显密钥。

默认数据库位置：

- macOS：`~/Library/Application Support/com.lingjing.mozhou/mozhou.db`
- Windows：`%LOCALAPPDATA%\Mozhou\mozhou.db`
- Linux：`$XDG_DATA_HOME/mozhou/mozhou.db`，未配置 XDG 时使用 `~/.local/share/mozhou/mozhou.db`

可用 `MOZHOU_DATA_DIR` 显式选择其他目录。显式选择时不会自动导入当前目录的旧库；如需指定旧库目录，可同时设置 `MOZHOU_LEGACY_DATA_DIR`。升级备份保存在数据库同级的 `backups/` 目录。

浏览器工作台默认位于 `http://127.0.0.1:5173`，本地 API 位于 `http://127.0.0.1:8765`。如果 5173 已被占用，Vite 会选择下一个可用端口。
浏览器开发脚本会显式启用无会话令牌兼容模式，并在 API 终端打印安全警告；该模式不用于桌面发行包。

桌面开发时直接启动 Tauri。命令会先生成当前平台的独立 FastAPI sidecar；桌面进程会自行选择动态本地端口、生成只存在内存中的 256-bit 启动会话令牌、等待健康检查，并在退出时回收 API：

```bash
pnpm run desktop:dev
```

## 验证

```bash
pnpm run verify
```

`verify` 会依次运行前后端 lint、严格类型检查、前端交互测试、后端测试、规模基准、生产构建、独立 sidecar 构建与桌面 Rust 编译检查。当前为 181 项前端测试、465 项后端测试、8 项常规 Rust 测试和 16 项工程脚本测试；另有 1 项真实 macOS Keychain 往返测试按需执行并已通过。规模门覆盖 1/30/100 章项目打开、30 万字检索、切章、保存和 300 万字参考切分。

桌面安装包构建：

```bash
pnpm run desktop:build
```

构建脚本会在系统临时 target 目录完成 release 签名和打包，再把安装器复制到 `artifacts/desktop/`。macOS 无发布证书时产出可本机测试的 ad-hoc 签名 DMG；配置 `APPLE_SIGNING_IDENTITY` 后，PyInstaller 与 Tauri 会共用同一证书并保持 Hardened Runtime，公证仍需要 Apple 发布凭据。Windows 需在 Windows 机器原生构建对应安装器。

严格标签流水线见 `.github/workflows/release-candidate.yml`：缺 Developer ID/公证或 Azure Artifact Signing 凭据时直接失败，不会把无签名包伪装成发布候选。每个平台生成 CycloneDX SBOM、第三方 NOTICE、SHA-256、工具链/源提交记录，以及 GitHub provenance 与 SBOM attestation。人工安装、升级、卸载保留和回滚矩阵见 [桌面发布清单](docs/product/release-checklist.md)。
